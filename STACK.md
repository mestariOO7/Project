# Обоснование выбора технологического стека

**Проект:** Flow Kanban. **Архитектура:** клиент-серверный модульный монолит.

| Слой | Технология | Обоснование |
|---|---|---|
| Frontend | React + TypeScript + Vite | Компонентный UI, типизация, быстрый цикл разработки |
| Backend | Node.js + Express + TypeScript | Простой REST API и общий язык с frontend |
| Данные | PostgreSQL + Prisma ORM | Реляционные связи между пользователями, проектами, досками, задачами и историей; типизированный доступ к БД |
| Аутентификация | JWT + bcrypt | Stateless API, хеширование паролей с солью |
| Валидация и HTTP-защита | Zod, Helmet, express-rate-limit | Проверка формы запросов, базовые HTTP-заголовки безопасности и ограничение частоты запросов |
| Unit-тесты | Vitest | Быстрый запуск TypeScript-тестов |
| Контейнеризация | Docker Compose | Повторяемое локальное окружение с PostgreSQL, API и UI |
| CI | GitHub Actions | Автоматический запуск тестов и сборок при push и pull request |

## Альтернативы

- Vue 3 / Angular вместо React: также подходят, но React выбран ради распространённости и экосистемы.
- FastAPI / Django вместо Express: хорошие альтернативы, но TypeScript упрощает совместное сопровождение клиентской и серверной частей.
- MySQL / MongoDB вместо PostgreSQL: MySQL подходит для реляционной модели; MongoDB менее удобна для связей и целостности данных данного приложения.
- Cypress вместо Playwright: оба подходят для E2E; Playwright удобен для нескольких браузеров.
- GitLab CI вместо GitHub Actions: зависит от платформы хранения репозитория.

## Ограничения и обоснование архитектуры

Для лабораторной выбран модульный монолит, так как он проще в разработке и тестировании, чем микросервисы. Перед production-развёртыванием необходимо настроить миграции Prisma, секреты, HTTPS/reverse proxy, резервное копирование, мониторинг, более строгую авторизацию на уровне членства в проектах, интеграционные и E2E-тесты.
